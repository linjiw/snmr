# Completion loop: frozen evidence to paper, video, and pre-hardware runtime

Started 2026-08-10 after an overnight audit found the frozen E70 recovery and paper/video
supervisors healthy but capacity-blocked by unrelated GPU workloads.

Objective: complete the unchanged three-seed E70 assay, bind its only eligible final analyzer into
the paper and failure-honest simulation video, and qualify the frozen explicit ONNX candidate
through the production inference contract and loopback CPU simulation without sending a real robot
command.

Primary scientific metric: hierarchical paired ambiguity-start SNMR-minus-time completion over the
69 frozen frame pairs and training seeds 0, 1, and 2.  Required content diagnostic:
SNMR-minus-phase-shuffled latent.  Deployment metrics are separate: runtime contract identity,
finite commands, exact joint order, joint-limit margin, latency/deadlines, stop behavior, and
simulation survival.

Maximum iterations: 25.

The detailed scope, success rules, stopping rules, video contract, and post-E70 research direction
are in `docs/RESEARCH_GOAL_2026-08-10.md`.

The first deployment iterations found a real safety defect that ONNX self-parity could not expose.
The original explicit export was replaced, for deployment only, by a 95%-range bounded export.  It
passes the exact production computation contract.  A supported-start loopback then remained
upright for 500 unassisted motion frames, but the gate correctly failed on a 0.00279-rad measured
joint-limit overshoot and collapse during the production stop transition.  The next iteration is
therefore a safe-state/dynamic-margin experiment, not a new learning run or a relaxed threshold.

The declared safe90 replay removed the dynamic joint-limit overshoot but caused posture and
velocity regressions under the same loopback.  It is discarded.  Once E70 closes, the deployment
candidate should be trained with the projection active rather than clipped more aggressively only
at export.

Repeated timing diagnostics then showed that the apparent stop failure began after the registered
motion window, when a continuous walking reference froze on an unstable frame.  A hold-last
prototype was discarded.  The retained production solution switches from WBT to Holosoma's
default zero-velocity locomotion safety policy before terminal freeze.  After moving the blocking
stiff-hold confirmation before the first physics step, three consecutive trials pass the full
loopback gate with zero safety violations.  This closes the selected CPU pre-hardware runtime gate;
robustness, independent-engine, HIL, and hardware stages remain unopened.

A publication-path audit then found that the draft prose and video result card assumed a favorable
three-seed outcome even though the frozen analyzer can return a scoped null or invalidate the assay
when the explicit control fails.  The paper macro generator and compositor now require both frozen
gates and select one of those three interpretations.  Synthetic positive, null, and invalid inputs
all build as six-page letter PDFs; unit tests cover the corresponding video labels.  This is an
intentional pre-analysis code refreeze, not an endpoint or outcome-language change.

The encoding supervisor's completion marker is not treated as visual acceptance.  A final bundle
auditor now requires an end-to-end visual-review record bound to the exact MP4 and contact-sheet
hashes, then cross-checks the analyzer, generated paper macros, PDF compliance, raw capture index,
video validation, and frozen code before it can certify the bundle.

The final repository regression passes 267 tests with 4 skips.  On this shared host the unbounded
PyTorch/OpenMP run oversubscribed a small decoder operation; the semantically identical run with
`OMP_NUM_THREADS=1 MKL_NUM_THREADS=1` completed in 182.88 seconds.

The visual-review record is now generated by a tested helper rather than hand-written.  It requires
explicit confirmation that the full video was watched, requires every frozen visual check to pass,
computes both media hashes itself, and refuses to overwrite an earlier review.  This closes the last
manual-transcription gap before the final bundle auditor.

After adding the recorder, the bounded-thread full regression passes 272 tests with 4 skips in
177.76 seconds; the 27 warnings are the same known tensor-conversion and TorchScript deprecation
warnings as the preceding run.

On the 2026-08-11 resumed audit, all five frozen confirmation files, all 24 retained deployment
files, and all 12 publication files replay their recorded SHA-256 values.  GPU memory improved to
22.53 GiB free after one unrelated job ended, but remains below the unchanged 26 GiB E70 gate.

All six pages of the synthetic positive-outcome draft were rendered and visually inspected.  The
title, abstract, diagrams, tables, two-column flow, limitations, conclusion, and references show no
clipping or overflow; page 6 contains only the last eight references.  This validates layout only
and is deliberately not recorded as review of the still-pending final-result PDF or simulation MP4.

A second resumed audit hardened the final certifier itself.  It now independently requires the
review record's full-video confirmation and a parseable UTC timestamp, then replays all 18 indexed
raw-video, capture-report, and checkpoint hashes from disk.  Cross-binding JSON fields alone is no
longer sufficient to certify provenance.

The post-hardening full regression passes 277 tests with 4 skips and the same 27 known warnings in
174.21 seconds under the bounded-thread configuration.

CLI-level smoke then exposed an installed ROS package also named `scripts`, which direct entrypoint
execution could resolve before this repository.  The evaluator, visual-review recorder, and final
auditor now put the repository root first explicitly.  Exact SNMR help commands and the exact
Holosoma/WBT Tyro parse pass, followed by a 279-pass/4-skip full regression in 172.84 seconds.

Three consecutive audits after goal resumption observed the same capacity condition.  The third,
at 2026-08-11T20:39Z, found 22.531 GiB free against the unchanged 26 GiB gate, with the unrelated
Cosmos process holding 7.35 GiB.  Both detached supervisors remain healthy, all 41 frozen files
across confirmation/deployment/publication still match, and no final marker exists.  With every
result-independent completion task exhausted, the goal is correctly recorded as externally
blocked rather than weakening the gate or disturbing that process.
