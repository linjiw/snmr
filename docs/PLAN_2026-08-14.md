## 3. The strategic finding: P1 answers the wrong attack

The strongest reviewer attack, named by the external review itself, is:

> "The reported A−T difference may only show that the SNMR latent supplies one bit of clip or
> teacher identity. Given that both trajectories are memorized, this does not establish meaningful
> motion representation."

Consider the two hypotheses that matter:

- `H_id` — `z_cmd` carries exactly one bit: which clip.
- `H_content` — `z_cmd` carries time-varying within-clip trajectory state.

**P1 predicts a positive `Δswap` under both.** Under `H_id` it predicts a *maximal* one. P1
therefore supplies **zero likelihood ratio** between the two hypotheses the paper's title asks about.
`docs/E71_COMMAND_SWAP_PROTOCOL.md` :38-40 says so directly: *"Neither result separates dynamic
trajectory content from static clip identity."* So does `PAPER_STRENGTHENING_DESIGN` :294. But §9 of
that same document schedules P1 at positions 2–5 and P2 at position 6, and §10 claims the P1-bearing
revision "directly answers the strongest reviewer attack." It does not.

**What P1 does earn**, and it is real: it upgrades the ladder from *the channel is necessary*
(destruction) to *the channel steers a frozen controller toward the branch it names*. That makes the
word **command** defensible, and it produces the single most ICRA-legible artifact this project
could make — a same-state / different-command video. P1's case is the demonstration, not the rung.

**What actually moves the identity attack** is the latent-substitution battery (P2). And there is a
route to it that neither the design doc nor the protocol identified.

### 3.1 P2 can run on the frozen E70 instrument with zero code changes

`snmr/integration/wbt_latent.py` loads `latent_z` **from the motion NPZ**
(`wbt_latent.py:55-61, 231-240`), and in eval-only mode `train_e52_dagger.py:266-270` restores
`z_mean`/`z_std` **from the student checkpoint**, so substituting the latents cannot corrupt
standardization. Therefore:

> Write a new motion directory whose NPZs are byte-identical in `joint_pos`, `joint_vel`,
> `body_*` — identical physics, identical reference target — and differ **only** in `latent_z`.
> Point the frozen eval-only path at it with `E52_EVAL_STARTS_JSON` = the frozen 69-window precheck.

That yields the P2 interventions through **the exact instrument that produced Table I**, with:

- no edit to any file in the confirmation hash manifest;
- no dependence on the never-simulator-tested E71 evaluator;
- an outcome (ambiguity completion) **directly comparable to the frozen 0.754 / 0.562 / 0.552**.

Arms, all as substituted `latent_z` tensors:

| Arm | `latent_z` substitution | Question |
| --- | --- | --- |
| δ = 0 control | unchanged | **Mandatory**: must reproduce 0.754 before anything is interpreted |
| δ = ±0.25 s, +0.5 s | rolled within-clip by ±12 / +25 frames | Is within-clip time-varying state used? |
| first-frame constant | `z[clip_start]` broadcast over the clip | Can a valid clip-specific constant retain performance? |
| clip-mean constant | `mean(z_clip)` broadcast | Can a static identity proxy retain performance? |

Cost: ~1 CPU hour to build the NPZs, ~15 evaluations at seconds of simulated time each — well under
one GPU hour for the whole battery, three seeds.

**Register the interpretation before running it.** The likely outcome is the identity outcome: the
frozen shuffled arm preserves matched-phase latent statistics, destroys clip consistency, and lands
at 0.5524 — i.e. at the time null (0.5622). That points at a clip-consistent carrier. Register the
asymmetry explicitly, because the strengthening doc currently asserts the invalid direction at
:321-322:

> Static-code **retention** is evidence for identity. Static-code **collapse** is **not** evidence
> for content — a constant `z` is outside the student's training input distribution, so collapse is
> confounded with distribution shift. Only the δ arms, which feed a real latent trajectory that is
> merely misaligned, are two-sided.

The identity outcome does **not** kill the paper. The frozen headline is a claim about a matched-null
*contrast*, not about what the content is; it survives verbatim. One interpretation sentence changes:
*"clip-disambiguating trajectory information"* → *"clip-disambiguating information consistent with a
static identity code."* The instrument was built to answer this question and returned a specific
answer — continuing the pattern (E63, E52-v4, E61b, E56-C) of the apparatus ruling against its
authors, which is this project's central credibility asset.

**The standing lesson:** the E71 apparatus is elaborate enough to convert an engineering mistake into
a *terminal scientific conclusion*. That is why Track D's instrument-failure/assay-failure split
below is non-negotiable — and it is why this retraction is recorded in place rather than deleted.

**Protocol patches to make before preregistration** (unfixable afterward):

- **Split instrument failure from assay failure.** The gate ANDs a *diagonal* condition
  (`C(cmd A)<0` from state side A — does the harness work at all?) with a *crossed* condition
  (`C(cmd B)>0` — is the branch separable?) and calls any failure terminal. A reset bug therefore
  becomes a permanent negative scientific result. Register a diagonal pass-rate threshold: broad
  diagonal failure = INSTRUMENT FAILURE, licensing a logged repair and re-run. Only a passing
  diagonal with a failing crossed condition is terminal.
- **Exclude the smoke pair** from the confirmatory support (69 → 68; the ≥20 threshold is
  unaffected). The smoke inspects real branch coordinates on a confirmatory cell, pre-registration,
  across an unbounded number of retries.
- **Deletion ledger.** The launcher refuses any cell whose log exists, and `tee` creates the log on
  every attempt including a fail-closed abort — so recovery *always* requires deleting files inside
  the "immutable" root. Make each deletion append-only and auditable (path, SHA, UTC, owner, reason),
  hash-bound into the certificate. Otherwise every retry is an invisible researcher degree of freedom.
- **Leave-one-component-out jackknife** rather than a hard concentration cap. `≥20 pairs across ≥6 of
  12 components` is satisfiable with 72% of mass in two components while the primary bootstrap
  resamples components. A cap adds a second terminal-failure mode; a jackknife does not.
- **Register N=25 and N=50 both, declare N=50 primary, forbid promotion of N=25** under any outcome.
- **Promote the all-69 descriptive `Δswap` from optional to required.** Explicit and SNMR students
  share the teacher ensemble, recipe, init seed and decoder input, so the explicit-defined gate is
  correlated with SNMR success through the shared trainer. A reviewer shown only the gated result
  suspects selection; one shown gated + all-69 with the same sign does not.
