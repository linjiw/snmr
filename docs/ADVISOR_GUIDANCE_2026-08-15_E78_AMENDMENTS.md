The reconciliation is sound, and the most important thing it did was catch that E77 falsifies the headline I proposed before you built toward it. "Latent-backed trackers degrade gracefully" is dead in its replacement form — the frozen SNMR student is worse at every severity, and the one positive was a laundered clean gap. The masked-fusion reframe is the correct salvage, and it's actually a better paper: the claim becomes *robustness is trained, not free*. You already have the internal precedent for that mechanism — E65 showed episodic train-time noise on z_cmd buys 18x hold robustness where a deterministic encoder collapses. E78 is the same medicine applied to the reference stream with content controls attached. Use that through-line explicitly; it turns E77 from an embarrassment into the motivating baseline (the frozen sweep cells literally *are* the "what dropout does to today's students" curve).

That said, I'd amend the E78 design in four ways before spending the GPU night, because the current arm list can't distinguish the outcomes you most need to separate.

**1. mGf (explicit future window, masked, FiLM) must be in the seed-0 sweep, not deferred.** mZf's held z window carries +0.1s of future content through every outage; mE's held g carries none. If mZf beats mE, the uncontrolled explanation is "100ms of lookahead," not "the representation." The plan already flags the future-`motion_command` lookup as required-before-any-claim and as shared plumbing with the paper's C-future arm — so build it first (it's a day against the derived-trainer pattern) and make mGf identical to mZf with u swapped: [g_t, g_{t+0.1s}] through the same projection and FiLM path. Otherwise you risk spending seeds 1–2 on a result whose decisive control arrives later and reverses the reading. Be honest about the prior here: for a single embodiment, explicit content is a superset of latent content, so mGf ≥ mZf is the likely outcome. That's fine — it's the HANDOFF-style "expose a future window across the interface" finding, cleaner and more actionable than a representation claim — but pre-commit to that interpretation now so nobody is tempted to spin it post hoc. If mZf ≥ mGf, you have a genuine representation result; either way the latent's *structural* monopoly retreats to cross-embodiment, which is point 4 below.

**2. Add a live-clock variant of the time control.** Scope-`all` freezes the encoder's upstream signal, so mTf's time code freezes during outages — but a deployed system never loses its clock. A reviewer will correctly say the time control is artificially handicapped. mTf-frozen is the right *matched-masking* control (keep it); add mTf-live, where the sinusoid code is computed from the tick counter and exempt from the masker. On the two-walk instrument, a live clock gives perfect progress but cannot disambiguate clips, so mTf-live isolates exactly "content beyond perfectly-known time under dropout." One flag in the masker, one more arm.

**3. Register the ambiguity-start grid under dropout as a co-secondary endpoint.** The general-grid severity sweep will be dominated by "keep walking in phase," where masked-trained mE can coast on proprioception (B reached 0.43 from scratch; a policy with flags will coast better) — which means the primary at f=0.3/seg 5–25 may have little headroom and the real effect may live at f=0.5 or 25–50-tick segments. Name the harder cell as a registered secondary *now*, not after seeing results. And the ambiguity starts are where content should separate hardest: an outage early in an ambiguous rollout leaves frozen z still saying which clip, while the time code by construction cannot. That cell is the sharpest test of mZf vs mTf/mShf and it costs only evaluation.

**4. Small bookkeeping before launch.** Pin the frozen sanity targets to the seed-exact, hash-bound E70 report values rather than the three-seed aggregates (0.923/0.699 are aggregate means; the seed-0 cells should reproduce seed-0 numbers). Confirm in the prereg that every masked arm, including mE, gets identical flag bits — if mE lacks them, part of mZf's edge is just "knowing when it's blind." And have the analyzer report both clean contrasts: mZf−mE (the registered co-primary) *and* mE−frozen_explicit, because if masking training itself costs several points clean, the deployment pitch changes and you want that number registered as a descriptive endpoint rather than discovered in review.

On the E1 pilot, one correction of emphasis before it propagates: the gate-clearing +0.117 is on the partly circular label set (SNMR students read z, so z predicting their failures is contaminated). The clean row — explicit-only labels — is +0.054, below the +0.10 gate, with the plausible excuse of label sparsity (77 event bins). So the honest status is "directionally positive on clean labels, gate-cleared only on circular ones; licenses E1-proper" — don't carry +0.117 forward as the expectation. For E1-proper this actually settles owner decision 2 by itself: use the `whole_body_tracking` pool hook. Vanilla PPO policies never see z, killing the circularity; the multi-clip pool enables real leave-clips-out; and the sampler's `bin_failed_count` EMA is the exact quantity E2 would warm-start, so the regression target is the deployment target. Export at multiple checkpoints (early-training failures ≠ late-training failures — either model per-checkpoint or use the time-averaged EMA), keep the per-clip mean-centering of z features, and note that adaptive sampling makes easy-bin estimates noisier via undersampling. The identity-stripping story takes care of itself under leave-clips-out, which is another reason to insist on ≥20 clips.

Answers to the three owner decisions: (1) yes, give E78 the next ≥26 GB night, but with the amended arm list and this order — frozen sanity evals (minutes), then mE and mZf trained first with a quick f-sweep eval to check the kill rule early, then if alive: mGf, mTf-frozen, mTf-live, mShf, mZc, mZg, mS. The paper's unmasked C-future run slots into any gap once the shared lookup exists — it's one training, and it converts the Limitations sentence into a measured non-issue, clearly labeled as a post-hoc, non-registered addition. (2) The pool hook, per above. (3) E78 seeds 1–2 before E3, and not just for scheduling reasons: E3's value is *conditional* on E78's outcome. If mZf loses to mTf or mGf, enriching z's content can't change that verdict and E3's tracking-side motivation collapses to its retargeting-side benefits; if mZf wins, E3's z' gets a validated harness where swapping the latent is a cheap follow-up arm. The one E3 component with independent value regardless is the low-weight contact-head sweep (E48-100k already prices weight 0.5 at +1.5 cm; 0.05–0.25 is unexplored), but it's GPU-competitive, so it still waits.

Two strategic items beyond the immediate queue. First, fix the E54 launcher now — the `set -euo pipefail` + validated-success-marker + GPU-precondition fixes are listed and are CPU work — and hold E54 Stage-0 (T1 teacher) as the first job after E78's seed-0 kill decision. Cross-embodiment is where the latent has a monopoly no explicit arm can contest (a 29-DoF command stream structurally cannot drive T1), which makes it the program's insurance policy against both E78 failure modes: if fusion dies, the latent's remaining home is cross-embodiment; if fusion succeeds via the exposure-study reading, cross-embodiment is still the CoRL-scale differentiator. The port is done and the blocker was twice infrastructural, not scientific — don't let it slip a third time. Second, the UniAct claim stays out of any related-work sentence until someone actually reads the paper, and note that even if verified it addresses compression, not trained fallback, so it's context rather than precedent.
